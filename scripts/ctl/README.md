# scripts/ctl — the controller's mechanical work as verbs (owner's order, 2026-09-21)

`scripts/ctl/ctl <verb>` is the only door for: landing a PR, the forced gate, opening a PR, anchoring the controller state, verifying a batch PR, reconciling the ledger, watching lanes (`ctl seats [--flag]`: one read-only line per tmux seat — busy/idle, monitors, input box, Ctx, branch, last DONE/CHECKPOINT; `--flag` lists only seats needing action), restarting an executor (`ctl restart <window> <worktree> <brief> [--override FILE] [--model M] [--effort E]`: `--model` is an alias or full model name, `--effort` one of `low medium high xhigh max`; both are appended to the launch line as claude's own flags (`claude --help`: "`--effort <level>` Effort level for the current session (low, medium, high, xhigh, max)"), `exec-claude.sh` lets a caller's value win over its opus / high defaults, and without them the pasted line is byte-identical to before; a bad value fails before the supersede marker is written and before the window is killed; on the DeepSeek backend `--model` would override the env file's model, so leave it off there), closing an idle lane (`ctl close <window>`: refuses the controller, the planner, a running turn, and a dirty or unpushed worktree), delivering a message to a pane, rebuilding the dev stack. `ctl run-tests` (below) is available for test/typecheck/build runs but is not yet enforced: the PreToolUse hook does not refuse a raw `vitest`/`tsc` (briefs and the lane prompt carry that rule). A PreToolUse hook (`hooks/ctl-scripts-only.py`) refuses the other raw forms in every Claude Code session on this machine; `ctl help` lists the verbs, each prints one summary line last (`OK …` / `FAIL …`), exits 0 only when every named condition held, and takes `--dry-run`.

## The marker chain
`ctl check-pr <branch>` (green) writes `.git/ctl/checked-<sha>`; `ctl pr open --require-checked` refuses without it. `ctl gate <sha>` (green) writes `.git/ctl/gate-<sha>`; `ctl land <pr>` refuses without it and re-reads the PR head at the instant of merging. A marker names one sha; a new commit needs a new run. `ctl gate` first fetches `origin/main` and refuses unless HEAD already contains it — a `--merge` landing is then content-identical to the gated head (otherwise the merge commit's tree is a union the gate never saw); merge `origin/main` into the branch and re-gate.

## `--base <branch>` — the integration ref (default `main`)
A merge to `main` deploys to production; work integrates on a `release/<name>` branch. `ctl gate`, `ctl land` and `ctl check-pr` take `--base <branch>` and measure against `origin/<base>` instead of `origin/main`. **Only `main` or `release/<name>` is accepted** (a task branch, `develop`, `release/`, `release/../main`, an empty value all refuse before anything runs).
- **`ctl gate <sha> --base B`** — fetches `origin/B` and refuses unless HEAD contains it (the remedy it prints names `origin/B` and repeats `--base B`). Green writes the marker `gate.release+<name>-<sha>` (`/` → `+`), **not** `gate-<sha>`.
- **`ctl land <pr> --base B`** — the PR's base must EQUAL `B` (checked at the start and again at the instant of merging, so a PR retargeted after the checks is refused), the gate marker must be the one for `B`, the ancestry re-read, the reachability, tree-identity and drop checks all read `origin/B`, and the primary checkout is fast-forwarded only when it stands on `B`.
- **`ctl check-pr <branch> --base B`** — the diff and the commit list are taken against `origin/B`; green writes `checked.release+<name>-<sha>`. **`ctl pr open --base B --require-checked`** looks for the marker of that same base.
- **Why main cannot be reached this way.** The default is `main` and its behaviour, its `gate-<sha>` / `checked-<sha>` marker names and its refusal messages are unchanged. A release-kind marker satisfies no landing or PR to `main`, and a `main`-kind marker satisfies none to a release branch; `land` merges only a PR whose base equals `--base`, so `--base release/x` can never merge into `main`. Landing into `main` is still the owner's word, per merge: run `ctl land <pr>` (no `--base`) only when they have said so.
- Known limit: `check-pr` still reads the plan and progress file it was always given (`--plan FILE`; the progress path is `docs/lanes/release-2026-09-22-progress.md`), so a release branch that does not carry them needs them supplied or the batch conditions do not apply.

## `ctl run-tests` — one door for test, tsc and build runs (owner-approved 2026-10-03, plan #12 + #17)
`scripts/ctl/ctl run-tests [--repo W] [--label L] [--max-min N] [--dry-run] -- <command…>` runs any vitest / tsc / build command with its WHOLE output in `~/.cache/gisik-ctl/run-tests-*.log` and prints at most 30 lines: the counts (`Test Files` / `Tests`, `tsc: N errors`, turbo `Tasks:`), the first failure's name and assertion, the queue wait, the log path and `exit code: N`. **The verb's exit code is the command's own** (never masked; a signal-killed command is 128+signal); **75** means no slot came free within `CTL_SEM_MAX_WAIT` and nothing was run. **124** with a `TIMEOUT after N min` last line means the cap below stopped it. Everything after the first `--` reaches the command untouched, `--dry-run` and `--repo` included. **Where the command runs:** in the directory you called it from (it is always inside the repo, which is derived from it), so `pnpm exec vitest run test/x.test.tsx` works from a package directory; with `--repo W` it runs in `W`. The directory is printed in the summary's first line (`(in <dir>)`), the log header and the `--dry-run` line. Run under Node 22; one command per call, so quote a shell line as `-- sh -c '…'`.

**The semaphore.** A machine-wide slot (state in `~/.cache/gisik-ctl/sem`, override `CTL_SEM_DIR`; NOT per checkout). Slots default to **2**: `$CTL_SEM_DIR/slots` (a number) wins over `CTL_TEST_SLOTS`, which wins over 2, so two callers cannot disagree. A slot is granted only when ALL of these hold, polled every **1 s** (`CTL_SEM_POLL_SECS`; a poll is a few `[ -d ]` tests and a `ps` per holder, so a freed slot is taken within a second instead of sitting empty up to 5 s):
- **no `ctl gate` is running, or fewer than the gate cap (`CTL_SEM_GATE_SLOTS` / `gate-slots`) slots are held** — the gate writes `gate-<pid>` around its real run (never on `--dry-run`); while it is live a new slot is granted only while fewer than the gate cap (default **1**) are held, counted after the stale ones are reclaimed, and slots already running finish. `CTL_SEM_GATE_SLOTS=0` is the old rule (no new slot while a gate runs). The cap is `CTL_SEM_GATE_SLOTS` when set to a number, else the content of the `gate-slots` file in the semaphore dir (`~/.cache/gisik-ctl/sem/gate-slots`, whitespace trimmed, a non-negative integer), else 1; an empty or non-numeric file falls through to 1, never to 0. The value is re-read on every poll, so `echo 2 > ~/.cache/gisik-ctl/sem/gate-slots` takes effect for waiters already in the queue, with no restart. A gate that begins between a run's claim and its start makes the run give the slot back when, counting that claim, more than the gate cap are held. The pressure and swap-in probes below still bind under the cap, and a wait the cap causes is still recorded as `gate`. Why 1, not 0 (planner 2026-10-04, P25): in 16:41–17:41 the `gate` reason was 112 of 219 slot-wait minutes while three gates ran 15 minutes in all, and the slots drained idle behind each gate (101 of 180 slot-minutes used).
- **memory pressure is normal** — `sysctl kern.memorystatus_vm_pressure_level` = 1 (2 warn and 4 critical wait) and `memory_pressure`'s "System-wide memory free percentage" ≥ `CTL_SEM_MIN_FREE_PCT` (15). The probe only READS; `memory_pressure -l/-p` would simulate pressure and is never used.
- **the swap-in rate is low** — `vm_stat`'s `Swapins` counter × the page size over a 3 s window (`CTL_SEM_SAMPLE_SECS`), under `CTL_SEM_MAX_SWAPIN_MBS` (**8 MB/s**, 512 pages/s at 16 KiB); it takes TWO consecutive high windows to block (one window is a blip).
  - **The verdict is shared** (13.2310–13.2317; planner P48, 2026-10-05: ~800 slot jobs/h each paid a 3 s probe, ~40 seat-min/h): a sample's result is written to `$CTL_SEM_DIR/swap.verdict` as `<epoch> <ok|high>` (stamped when the sample ENDS), and every waiter reuses a verdict at most `CTL_SEM_SWAP_TTL` (**10 s**) old instead of sampling — a reused `high` blocks exactly as a sampled one. Only a missing, stale, unparsable or future-stamped verdict samples (two windows, the rule above). So a grant with a fresh verdict on file costs no sleep; a COLD one (nothing sampled for 10 s) still pays one 3 s window.
  - Measured 2026-10-03 on this 16 GB machine, five lanes live, swap 6.8 of 8 GB used: idle 3 s windows read 1 1 2 0 1 6 253 78 2 1 pages/s (the 253 = 4 MB/s was a single blip); under one real `vitest run` of `@gisik-nokma/ui` (65 files, 847 tests, 27 s, 2 workers) 0–110 pages/s; under two at once 2–57 pages/s. The threshold is 2× the largest idle blip and 5× the largest loaded reading, well under what thrashing looks like; retune from `waits.tsv`.

**Stale holders.** A slot or gate marker whose pid is dead, or alive with another start time (pid reuse; the start time is `ps -o lstart=` rendered with `LC_ALL=C TZ=UTC0`, so every caller reads the same string whatever its own TZ or locale), is reclaimed (atomic rename, so one waiter wins); a slot dir with no holder file is a claim in progress for 10 s (`CTL_SEM_GRACE_SECS`) and reclaimed after. A slot is released on every exit path, including ^C and SIGTERM (and only while its holder file still names this run, so a wrongly reclaimed slot, or a holder-less one that is another waiter's claim in progress, cannot be taken with it): the command runs in its own process group and the whole group is stopped first (TERM, KILL after 5 s) — signalling only the direct `pnpm` left vitest workers orphaned at ppid 1 (measured), which `ctl gate` refuses.

**The queue wait is logged on every run**: printed as `queue wait: 28s (waited for: slots)` (or `(slot 1/2)` when nothing waited; reasons `gate`, `slots`, `pressure`, `swap`), and appended as `time, label, seconds, reason, slots, probe_secs` to `$CTL_SEM_DIR/waits.tsv` — the history the slot count is tuned from. The seconds exclude the grant poll's own sampling time (a measurement, not a wait), which is the 6th column: 0 when a shared verdict was reused, 3 (or 6, two windows) when the grant sampled; wait + probe = queue entry to grant. A ctl that predates this change writes 5 columns (every row before it landed on 2026-10-05, and any run through an older checkout's ctl since), so a reader of the 6th column must allow for a 5-column row. Measured 2026-10-03 (three `vitest run` of the ui package started a second apart, 2 slots): waits 0 s, 0 s, 28 s — the third started when the first finished.

**Playwright ports** (13.2280–13.2286; the two browser packages pin their dev-server port with `reuseExistingServer: false`, so a second run on a held port is RED, not a wait — it cost two painter gates on 2026-10-05). Each package reads its port from the environment and defaults to the old one: `knowledge-graph-browser` `KG_PW_PORT` (3191), `flow-graph-browser` `FG_PW_PORT` (3192; its config follows with the WG twin). `ctl gate` exports `KG_PW_PORT=3291 FG_PW_PORT=3292` (the dry-run line names them; turbo hands `KG_PW_PORT` to the browser task through its `passThroughEnv`, which leaves the task hash alone), so a gate never meets a lane's or a reviewer's run on the defaults. `ctl run-tests` gives a command that names `playwright`, a `*-graph-browser` package or `turbo` (or runs in one's directory) a FREE pair of its own in `KG_PW_PORT` / `FG_PW_PORT`: `verbs/pw-ports.py` walks 3300–3399 from the window of its slot (10 ports per slot, so two concurrent runs never start on the same port) to the first ports nothing listens on — a plain bind of 127.0.0.1 and of ::1 must succeed, so a listener on either, or on the wildcard 0.0.0.0 / `::` (a server started with no host), holds the port; no `SO_REUSEADDR`, which on macOS lets a bind succeed beside a wildcard listener; a port in TIME_WAIT is skipped too — and the summary prints `ports: …`. The trigger reads the whole command, not the 120-character line it shows. A value the caller already exported stays (either port); any other command runs with its environment untouched. Seam: `CTL_PW_PORT_BASE` (tests).

**The cap: `--max-min N`** (13.2320–13.2329; planner P47 2026-10-05: a mutant's synchronous infinite loop held a slot 13+ min at 99.7 % CPU, and vitest's `testTimeout` cannot stop one). N minutes of SLOT time: the clock starts once the slot is taken, so the queue wait never counts. **Default 30** (planner ruling 14:36). `GISIK_RUN_MAX_MIN` overrides the default. `--max-min 0` means no cap, and only as an explicit flag: `GISIK_RUN_MAX_MIN=0` is refused (exit 64). On expiry the job's WHOLE process group gets TERM and, 10 s later, KILL. The job always runs in its own group (`set -m`), so nothing outside it is touched. Then the slot is released, `TIMEOUT after N min` is appended as the log's last line, the summary's last line reads `FAIL run-tests <label> TIMEOUT after N min …`, and the verb exits **124**. A command's OWN exit 124 (and `ctl mutate`'s watchdog's) prints no `TIMEOUT` line, so a driver tells a cap stop by 124 PLUS that line, never by the code alone. The timer is ONE background `perl` process (no children) that signals only its own parent, the verb (`getppid`: a timer whose verb died signals nothing). Every exit path stops it by KILL to its pid; the first, subshell-based timer orphaned its `sleep` in 25 of 40 instant-exit runs and once lost its TERM in the fork window (13.2326). The log header and `--dry-run` name the cap. **Callers:** a mutant driver passes `--max-min 10` per mutant job; a battery or `pnpm check:ctl` over 30 min passes `--max-min 60` (or is split); `ctl mutate` passes its own (its watchdog's cap + 2 min, so its watchdog always fires first). A 124 + TIMEOUT is reported separately and judged by the reviewer, never folded into RED or GREEN. Seams: `CTL_RUN_SECS_PER_MIN` (60), `CTL_RUN_KILL_GRACE_SECS` (10). The CI half: every `ci.yml` job has `timeout-minutes` (13.2327).

**Known limits.** The gate does not wait for running slots, and with the default cap one run may start beside it (the task pin: it only gets the priority marker; plan #12's "waits only for running slots to finish" is an open question). No FIFO ticketing: waiters race on `mkdir`. A verb killed with SIGKILL leaves its command running until it ends; its slot is reclaimed as stale at once.

## `ctl mutate` — Stryker plus the custom classes on a branch's changed lines (owner-approved 2026-10-04, process finding P20)
`scripts/ctl/ctl mutate [--repo <worktree>] [--base <ref>] [--dry-run] [--json]` mutates ONLY the changed non-test source lines of the branch (`git diff <merge-base>..HEAD`, added lines in new-file numbering; `*.ts`/`*.tsx`, never `*.test.*`, `*.spec.*`, a `test/`, `tests/` or `__tests__/` directory, `*.generated.ts` or `*.d.ts`).
- **The base.** Default: the merge-base with the `origin/release/*` the branch shares the most history with (a tie refuses). A STACKED branch passes its parent: `--base task/<parent>`. The REVIEW line's `base=` is the rule. A tracked dirty tree refuses (commit first).
- **Skipped, and listed as SKIPPED:** a file in a package without `vitest` in its dependencies (the playwright `*-browser` harnesses), and a file outside any package. **`apps/server` needs the TEST Postgres** `127.0.0.1:54329` (`CTL_MUTATE_PG_HOST` / `CTL_MUTATE_PG_PORT`): when it does not answer, each server file is a TOOL-FAILURE (exit 2, the dry run too), never a skip; the other files are still swept (planner ruling 19:25).
- **Own tests only** (`verbs/mutate-tests.mjs`, planner ruling 19:25, `task/ctl-mutate-server`): a file runs only the test files in its package's `test/` (the whole package when there is none) that import it directly or through ONE re-export (`export … from`). An import is a static, side-effect or dynamic `import`, or `vi.importActual`; never `import type` or `vi.mock`; relative specifiers only (`.js` → `.ts`, `/index`). The list is the run's vitest `include` (`vitest.related` off), so the dry run, every mutant and every STATIC mutant's re-run see only those files; the report must show a non-empty subset of them, else exit 2. `ignoreStatic` stays off: a module-level constant only a DISTANT test kills (a route reached through `buildTestApp`) is a SURVIVOR to triage. **NO OWN TEST** (ruling 12:40): a file no own test imports runs with one generated sentinel test (exactly one test, checked; never Stryker's `testFiles: []`, which means the whole suite), every mutant is a no-coverage survivor and the table says `NO OWN TEST <file> n=<mutants>`: its survivors mean "no test in reach", NOT "the tests are weak"; hand-mutate such a file on the real suite. **STATICS NOT SWEPT** (ruling 19:25 (2)): a chunk the watchdog stops at the cap is retried ONCE with `ignoreStatic` on; its static mutants then report Ignored and the table says `STATICS NOT SWEPT: <file> n=<count>` (not a failure: exit 0 when nothing survived; list it in the HANDOFF); a retry that overruns too is exit 2.
- **Python 3.11 or later** (the watchdog's `Popen(process_group=0)`): `mutate.sh` refuses an older `python3` on PATH before anything runs (macOS's `/usr/bin/python3` is 3.9).
- **The custom classes Stryker lacks** (`verbs/mutate-ast.mjs`, the TypeScript AST of the file): every non-zero numeric literal ×10 and ÷10 (not in a type, an enum initialiser or a property name; the skipped count is printed by reason), and `Math.ceil` ↔ `Math.floor`, either ↔ `Math.round`. Every `x as T` (`as const` too) on a changed line is blanked to spaces first: Stryker never mutates inside a cast (the spike's TL4 O3/O4). **Planner ruling 16:40 (B):** each custom mutant is injected into the file as a switch Stryker itself flips, on the SAME line (`200` → `(false ? 2000 : false ? 20 : 200)`), so it runs inside the file's one Stryker slot-run with per-test coverage. Exactly one flip is counted per alternative (the flips that re-select the original, and duplicates, are dropped); the run asserts `custom injected == counted` and a mismatch is exit 2. A file whose injected copy does not parse falls back, for that file only and saying so, to one `vitest run` per custom mutant (`CTL_MUTATE_INJECT_FAIL` is that branch's test seam).
- **Runs.** One `ctl run-tests` slot-run per FILE (Stryker 10, vitest runner by absolute plugin path, `coverageAnalysis: perTest`, `concurrency: 2`, `timeoutMS: 10000`, `vitest.related: false` (the own-test `include` is the cap), `inPlace: true`, `ignoreStatic: false`, `disableTypeChecks: false`: otherwise Stryker writes `// @ts-nocheck` into every src/test file of the package in place, and vitest never type-checks anyway); a file above 300 mutants (Stryker's own instrumenter counts them, no test run) is split into line ranges (`CTL_MUTATE_SPLIT`); a run that holds its slot past 600 s is stopped and the verb fails (`CTL_MUTATE_MAX_SECS`, P10). The cap is kept INSIDE the slot: the command runs under `mutate.py watchdog`, which run-tests starts only once it holds the slot, and which stops the command's process group (TERM, KILL 3 s later), so the queue wait (up to `CTL_SEM_MAX_WAIT`, a gate first) never counts. The outer timeout is only a backstop (the cap + `CTL_SEM_MAX_WAIT` + 63 s, `CTL_MUTATE_BACKSTOP_SECS`); a run still queued when it fires fails as `no test slot within …`, never as "a smaller split". The config is generated per run in a temp dir and removed. **Pool:** Stryker's runner forces vitest's threads pool, where a `process.env.TZ` a test sets does nothing (the repo's TZ CONTROLs then fail the dry run); the run uses a generated wrapper (of the package's `vitest.config.*` when it has one; it also sets the own-test `include`) (in `.stryker-tmp-ctlmutate-*-vitest/`, removed) that sends every file to forks, one at a time: vitest 3's own default. **Control:** after each run, `vitest list` of the same test files on the restored (unmutated) tree must find as many tests as Stryker's dry run saw on the injected copy; a difference is exit 2.
- **Output.** A table per file (mutants, killed, survived, no-coverage, timeout, runtime-error), each SURVIVOR as `file:line  mutator  original → replacement` (no-coverage counts as a survivor: no test reaches it), and RuntimeError / CompileError rows listed separately as triage items, never kills, in `~/.cache/gisik-ctl/mutate-<branch>-<sha8>.md`; one line `mutate: N survived (S stryker + C custom) in F files, M slot-min; log <path>`, then `OK …` / `FAIL …`. `--json` prints one JSON object before those lines. **Exit:** 0 no survivor, 1 survivors, including NO OWN TEST (normal: triage; ruling 14:47), 2 a tool failure, a crash of the verb included (`FAIL mutate tool failure: <type>: <message>` after its traceback, never Python's own exit 1).
- **Safety.** Every file written is first backed up and named in the temp dir's manifest; the wrapper's trap restores it on every exit (success, failure, SIGINT, SIGTERM), removes the Stryker temp dir (after moving back anything Stryker left in its in-place `backup-*/`: a Stryker stopped before its own restore leaves its originals there), and checks that `git status` is byte-identical to the start (otherwise exit 2). Nothing outside `--repo` is touched. `--dry-run` prints the ranges and the planned runs and runs nothing.
- **Lane protocol** (before the REVIEW line): run `ctl mutate`, and for EVERY survivor either add a leg or write a one-line equivalence reason in the HANDOFF's mutation table. The reviewer's own sample stays, for the classes no tool finds (a `!==` turned relational, a missing branch, a jsdom TypeError shown as RuntimeError).
- `bash scripts/ctl/test/mutate.test.sh` (13.2200–13.2223, 13.2228, 13.2229 and 13.2250–13.2269: scratch repos and a recording run-tests shim; six real Stryker runs on a fixture and one real run-tests queue, through a private semaphore dir).

## `CTL_TEST_ONLY` — run a slice of a ctl test file (process finding P21)
Every `scripts/ctl/test/*.test.sh` takes its `check` from `test/harness.sh`. `CTL_TEST_ONLY=<extended regex>` runs only the cases whose NAME matches (the file's own setup and teardown still run), prints `CTL_TEST_ONLY=<re>: N of M cases ran`, and exits 1 with `0 cases matched` when nothing matched; unset, the output is unchanged. A slice is valid only when its cases are self-contained (a case that leans on state an earlier case built must be sliced with it). **Mutation on `scripts/ctl/**`:** run a CONTROL of the slice that pins the mutated function on clean code first (`CTL_TEST_ONLY='13\.21(0[4-9]) ' bash scripts/ctl/test/<verb>.test.sh`, green), then each mutant against that slice, and re-run only the survivors on the FULL file. `bash scripts/ctl/test/harness.test.sh` (13.2224–13.2227).

## `ctl tipmerge` — the clean tip merge (owner-approved 2026-10-03)
`ctl tipmerge <branch> --base release/<name> --expect <sha> [--repo W] [--dry-run]` merges `origin/<base>` into `origin/<branch>` with no working tree: `git merge-tree --write-tree` computes the tree; if CLEAN the verb creates the merge commit (parents: branch tip, base tip), proves its tree and parents from the object database, pushes it to `<branch>` with a plain fast-forward push and re-reads origin with `ls-remote`; the last line is `OK tipmerge <branch> <sha40> …` and names `ctl gate <sha> --base <base>` (gate needs a checkout whose HEAD is that sha: from the gate checkout, `git fetch origin && git checkout --detach <sha>`; the lane's local branch is now behind origin — a lane that commits on it again must `git pull --ff-only` in its OWN worktree first, else its plain push is refused as non-fast-forward, which is safe). If CONFLICTED it prints `CONFLICT <path>` lines and exits **3**, pushing nothing — that case, a hand-resolved file, still goes to a lane and a reviewer fast path. `--expect` is **required** (7–40 hex: the READY sha); a branch that moved since is refused (exit 1). `<branch>` can never be `main`, any `release/*` name (even one that is no valid integration-branch name, such as `release/-x`) or `HEAD`; a failed fetch is a FAIL. A branch that already contains the base is `OK … already contains`, with no commit. `--dry-run` fetches and reports the verdict and the tree, creating and pushing nothing.

## The postman — `ctl post | inbox | ack | postman` (owner-approved 2026-10-03; design `docs/superpowers/specs/2026-10-03-ctl-postman-design.md`)
Inter-seat messages go through `roles/LEDGER.jsonl` (append-only; id, from, to, kind, body pointer). `ctl post <to> --kind next|fix|mergetip|question|note --body FILE | --text STR` posts; the daemon `ctl postman run` (tmux window `postman`) delivers the lowest-id open message per seat to `roles/postman/inbox/<seat>.jsonl` and, if no ack comes, as a ONE-LINE pane pointer after `pane_state` proves the pane safe (claude allowlist, not copy mode, no menu, no foreign box text; the planner seat is never pasted into). A seat's first action on a pointer is `ctl ack <id>` (in the SAME tool-call block as its first Read). `ctl inbox` lists my unacked messages; **`ctl inbox --watch` is the seat's ONE Monitor** (cursor file `~/.cache/gisik-ctl/cursor-<seat>-inbox`, at-least-once, no regex; a restart card's first step is `TaskStop` of every old monitor, then arm it). `ctl postman status` shows each seat's head message, tries and last result; `ctl postman audit` lists reviewer FIX / needs-tip verdicts with no delivered message. The bridge turns `QUEUE-dispatch.md` NEXT/FIX/MERGETIP/CLOSE lines into ONE note to `main` each (`needs ctl restart` / `needs ctl tipmerge` / `needs ctl close`; planner ruling 2026-10-04: a new task or FIX is a fresh `ctl restart`, a tip merge is `ctl tipmerge`, both the orchestrator's) — it NEVER pastes into a lane; a line it cannot parse is a `could not route` note. A message to the planner is a `⚑ POSTMAN → PLANNER` line in `CTL-TO-PLANNER-notes.md` (once, when delivered; a reminder at 30 min unacked). **Shadow run and audit (dispatcher retirement):** `ctl postman run --shadow` computes every delivery and writes ONLY `roles/postman/shadow.jsonl` (no ledger, inbox, notes, pane, DONE write-back or page). `ctl postman audit --parity` (or `--since <HH:MM|'YYYY-MM-DD HH:MM'|epoch>`, or `--window <n>` = the last n shadow QUEUE deliveries) compares it with `roles/DISPATCH-log.md`, `roles/QUEUE-dispatch.md` and the ledger: MATCHED (a dispatcher delivery paired with a shadow queue record of the same verb and lane whose name its REF WORDS agree with — the ref rule below, the same `ref_agrees` as a BY-ORCH agreement; REQUIRED, never preferred (planner ruling 2026-10-04 17:54), the earliest agreeing record wins — or a BY-ORCH agreement, below; the record no later than 2 min after the log line and no more than 45 min before it — the pairing window; each MATCHED line prints `ref=<words> ~ <the record's name>`), UNPAIRED (a dispatcher delivery with records of its verb + lane in the window but none it can pair, with ONE reason: `no-ref` when no word before its verb holds a letter, else `ref-mismatch`; the candidates are listed; `PAIRING matched N; unpaired N (ref-mismatch a, no-ref b); extra N` sums them), MISSED (a dispatcher delivery with no shadow record of its verb + lane to pair with; names the bridge's refusal), DUPLICATE (a surplus shadow record or two identical ledger messages in 10 min), EXTRA (a shadow delivery nothing matched, with ONE reason word), UNPARSED (a log line naming a verb and saying delivered/sent that pairs nothing); ## `ctl check-base <branch> <stated-base>` — is the base a REVIEW line states the base the branch was cut from? (planner ruling 2026-10-04, after the dispatcher's 01:36 flag)
Read-only. Where a branch was cut is read on its FIRST-PARENT line (tip, first parent, its first parent …): for the stated base, `origin/main` and every `origin/release/*` it counts the branch's first-parent commits that ref cannot reach (`git rev-list --first-parent --count <tip> ^origin/<ref>`, the fork distance). Another ref strictly nearer prints `WRONG-BASE <branch> stated=<B> closest=<R> (<n> vs <m> behind; forked <a> vs <b> first-parent commits back)` and exits 1; a tie (a branch exactly on a commit two releases share), a stale or far-behind but correct branch, and a branch that merged ANOTHER release in (planner arm (c): the merged release is a second parent, OK whichever release is deeper) are OK. The verdict depends on no release's length: counting commits *behind* (the ruling's wording, the first build's measurement) flags every stale branch whenever a younger release has fewer new commits; merge-base DEPTH (the second build) called a merged-in release the base whenever it was the deeper one. Consequence: merging the stated base into a branch cut elsewhere does NOT turn it OK — the branch still carries the other ref's commits; fix the base on the REVIEW line. The dispatcher's 01:36 flag (`task/sm2-g1-cls`) was a false positive: that branch was cut from KG (smoothness was already inside KG), and check-base says OK for it. ## `ctl autopilot` — the controller's matchmaking as a 60 s loop (planner MSG-orch-bottleneck-1, 2026-10-04)
`ctl autopilot once|run|start [--shadow] [--interval S]`: `once` = one pass, `run` = a pass every S s (default 60) under the singleton lock `$CTL_LOG_DIR/autopilot.lock.d` (mkdir + pid; a dead pid's lock is taken over), `start` = open tmux window `gisik:autopilot` running `run` with the same flags (`--dry-run` prints the line). Each pass logs every decision with its reason to stdout and `~/.cache/gisik-ctl/autopilot-<shadow|live>-<date>.log`. **`--shadow` logs `WOULD …` and writes nothing, sends nothing** (`class Door` in `verbs/autopilot.py` is the only code that appends a queue line, writes a PTR/boot/ledger or calls `ctl restart`; it returns first under `--shadow`, 13.2117). A pass, in order:
- **PULL files:** a reviewer that wrote `roles/PULL-<X>.boot` and is idle, box empty, clean (background shells are not counted: planner R1 2026-10-04 14:07, finding P13 — a seat parked on its own queued run-tests, or with a finished monitor's shell, shows `sh 1` while idle) is restarted on that boot at opus/high and the file removed only when the restart succeeded (a failure logs `FLAG restart failed` and keeps it) (the protocol of the controller's scratchpad pull-restarter, which this replaces — stop that loop before going live).
- **Free lanes** (idle, box empty, unpushed 0, dirty 0, its last line a DONE whose REVIEW line is queued — background shells then ignored (R1) —, or `CHECKPOINT reviewer idle after` with no open TOOK and 0 shells; not acted on in the last 180 s), fluid rule A.3: (1) an open `HH:MM FIX <KG|WG|lane N|N> <PTR-file> <task/branch>` line of `roles/QUEUE-autopilot.md` — **the controller writes that PTR** (FIX briefs stay judgement work), its first line `RUNG: <rung>` sets `--model/--effort`, the autopilot appends `HH:MM TOOK <line-time> <branch> (autopilot: lane N …)`; (2) while a reviewer FIX verdict of the pool (`DONE <time> FIX task/<b> … BRIEF-….md` — FIX is the word right after the cited time, so `DONE <time> READY … (FIX 1 delta)` is none; the controller's `TOOK <time> FIX task/<b>` ends it, a review TOOK does not) is under 15 min old (aged by day and clock, like items) with no such line, the lane WAITS; (3) the first row of its pool's order file whose Needs are all on the release tip; (4) the first row it can STACK on (≤ 2 unlanded levels, ONE unlanded base whose latest REVIEW line is at its origin head).
