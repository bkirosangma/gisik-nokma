## 22.1 Events

*Task 1. Ids `22.003`–`22.019` are unused.*

- ✅ **22.001 — `workspace.prefix_changed` is a registered event filed against the workspace and carries exactly one valid prefix (`{ prefix: "SH" }`);** control: `"sh"`, `"ABCD"`, `""`, `{}`, a stranger key and a non-workspace entity kind are all refused. Mutation: register it with `.passthrough()` or against the project kind → red. (`packages/domain/test/prefix-events.test.ts`; `packages/domain/src/events/membership.ts`, `vocabulary.ts`)
- ✅ **22.002 — `project.updated` may carry only a `prefix`, or only a `groupId` (a string, or `null` to ungroup);** control: `{}`, a malformed prefix (`"sh"`) and an empty `groupId` are refused. Mutation: drop `prefix` from the refine → the prefix-only payload is refused → red. (`packages/domain/test/prefix-events.test.ts`; `projectUpdatedPayload`)

## 22.2 Prefix history and derivation

*Task 2. Ids `22.028`–`22.039` are unused. `22.026` is a Task 2 follow-up (the reader-side half of 22.024).*

- ✅ **22.020 — after `project.updated {prefix:"SH"}` on a project founded with `SO`, the history reads current `SH`, former `[SO]` (with the instant it stopped), and its tickets' keys read `CCSH-n`;** control: before the update the keys read `CCSO-n` and there is no former. Mutation: leave `proj_projects.prefix` unchanged on update → red (also 22.021, 22.022, 22.026). (`apps/server/test/read/prefix-history.test.ts`; `apps/server/src/projections/proj-projects.ts`, `read/visible-projects.ts` `projectPrefixHistory`)
- ✅ **22.021 — a project founded with NO entered prefix (derived `SO`) that changes to `SH` records the DERIVED `SO` as former;** control: before, current `SO` and no former. Mutation: record nothing for derived projects → red (also 22.026 and 22.025). (same file)
- ✅ **22.022 — back to `SO` after `SH`: current `SO`, former `[SH]` only, `SO` no longer listed as former;** control: after the first move `SO` was former. Mutation: skip the DELETE of the new prefix's former row → red. (same file)
- ✅ **22.023 — `workspace.prefix_changed {prefix:"CD"}` makes keys read `CDSO-n` and `workspaceIdentityFromLedger` returns `formerPrefixes` `[CC]` with the instant; changing back to `CC` lists `CD` and not `CC`;** control: before, `CC`, no formers, `CCSO-n`. Mutation: ignore `prefix_changed` in the ledger read → red. (same file; `apps/server/src/workspaces/workspace-name.ts`; the six `13.101x`/`13.1027` identity cases gain `formerPrefixes: []` in `test/read/ticket-key.test.ts`)
- ✅ **22.024 — `resolveProjectPrefixes([{name:"Shop ops"}], new Set(["SO"]))` yields `SO2`, and with `SO`,`SO2` reserved `SO3`; an ENTERED `SO` is not moved by `reserved`;** control: without `reserved` it yields `SO`. Mutation: ignore `reserved` → red. (`packages/domain/test/prefix.test.ts`)
- ✅ **22.025 — `verify-projections` stays green after project prefix changes (including a return to a former prefix) and a `workspace.prefix_changed`, with `proj_project_prefixes` non-empty;** control: the registry declares `proj_projects` and `proj_project_prefixes`. Mutation: omit the new table from `tables` → the declaration assertion goes red. **The verify verdict alone does NOT catch that omission** (measured): a projection that writes an undeclared table has no shadow copy, the replay's `search_path` falls through to the LIVE table, which is emptied and rebuilt in place from the ledger and diffs nothing; `projection-order.test.ts` ("declares the tables it writes") pins the list too. (`prefix-history.test.ts`, `apps/server/test/projection-order.test.ts`)
- ✅ **22.027 — a project that moved `AA` → `BB` → `CC` lists its former prefixes `[AA, BB]` oldest first, with increasing `until` (each the `serverTime` of the move that left it);** control: current is `CC`. Mutation: `ORDER BY until_time DESC` in `projectPrefixHistory` → red (survived until this case). (`apps/server/test/read/prefix-history.test.ts`; `read/visible-projects.ts`)
- ✅ **22.026 — after project A (derived `SO`) moves to `SH`, a later project whose name derives `SO` reads `SO2` in BOTH readers (`projectPrefixesInWorkspace` and `visibleProjects`), because `SO` is reserved;** control: A reads `SH`, and before the move A held `SO`. Mutation: drop `reserved` from either reader → red. (`prefix-history.test.ts`)

## 22.3 The door

*Task 3. Ids `22.047`–`22.059` are unused.*

- ✅ **22.040 — `project.updated {prefix:"SO"}` on project B, where project A moved off `SO`, is refused `project.prefix-reserved` with *"SO was Shop operations' prefix until <d MMM, IST>. Its old ticket keys still point there, so it can't be reused."*; after A is renamed the text names A's CURRENT name (`Store's`);** control: `{prefix:"SX"}` is accepted. Mutation: drop the reserved branch → red (also 22.041, 22.044, 22.045). (`apps/server/test/permissions/prefix-reservation.test.ts`; `check-permission.ts` `checkPrefixReservation`)
- ✅ **22.041 — `project.created {prefix:"SO"}` on a retired prefix is refused the same way;** control: a free prefix on the same creation is accepted. Mutation: as 22.040. (same file)
- ✅ **22.042 — another project's CURRENT prefix is refused with the existing `project.prefix-taken` text, unchanged;** control: the prefix that project was retired from answers `project.prefix-reserved`. Mutation: skip the taken branch → red. (same file)
- ✅ **22.043 — `workspace.prefix_changed` by a member is refused `permission.role`; by an admin it is accepted.** Mutation: drop it from `ADMIN_ONLY_TYPES` → red. (same file)
- ✅ **22.044 — project A going `SO` → `SH` → `SO` is accepted at every step, and re-claiming its own former or current prefix is accepted;** control: another project asking for those prefixes is refused (`taken` for `SO`, `reserved` for `SH`). Mutation: stop excluding the project itself (taken or reserved) → red. (same file)
- ✅ **22.045 — through the real `POST /v1/events`, a re-delivered EARLIER event (`SO` → `SH`, sent after `SH` → `SO`) and a re-delivered LATEST one both answer `duplicate-event-id`, not a prefix refusal;** control: a NEW event from another project asking for `SH` is refused `project.prefix-reserved`. Mutation: stop excluding the project itself on either branch → red. The order of the two refusals is not pinned: the sets are disjoint (a held prefix is never another's former one), so swapping them is an equivalent mutant. (same file)
- ✅ **22.046 — the date in the reserved refusal is the IST day: a move whose `serverTime` is fixed at `2026-09-30T19:00:00Z` (IST 1 Oct 00:30, UTC 30 Sep) reads "… until 1 Oct.";** control: a move at `2026-09-30T06:00:00Z` reads "until 30 Sep". Mutation: `istDayOf(instant)` → `instant.slice(0, 10)` (the UTC day) → red (it survived 22.040, whose expectation was computed from a live `serverTime` far from a day boundary). (same file)
