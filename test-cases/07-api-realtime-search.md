**Stating a mutation's blast radius — a rule this file learned twice.** Name the CASES a mutation
kills, never the COUNT, unless the count is both deterministic and has been reproduced by a second
party. Two corrections earned this: "removing the `ORDER BY` reddens seven cases" was an artifact of a
single run (re-running gave 15, 18, 4, 15 — a query with no `ORDER BY` has no ordering guarantee, so
which assertions redden is a planner detail), and a "dies 6" for a visibility mutation measured 7 on
re-run, the two extra deaths being cases whose assertions are coupled to a shared fixture query's
length. **A count is a fact about one run unless something makes it a fact about the code.** The cases
are stable; the arithmetic over them is not.
