- **3.33** ✅ Online stream subscriber — the wire half. `streamUrl` turns an `http`/`https` origin into `ws`/`wss` + `/v1/stream`; `backoffDelayMs` doubles from 500 ms, caps at 30 s and applies ±20% jitter from an INJECTED `random`; `parseFrame` delivers all FIVE server frames (`event`, `purge`, `scope-revoked`, `caught-up`, `error`) with amendment 19's `workspaceId` intact, answers `ping` with `pong` without delivering it, and returns `null` for non-strings, unparseable JSON, `null`, and unknown `type`s — never guessing. `error.workspaceId` is `null` for connection-level errors. The relationship to the published `serverStreamFrameSchema` is pinned in ONE direction and deliberately: everything the schema accepts, `parseFrame` accepts — proved over a ULID-shaped fixture of every member, with the schema's own DERIVED option list asserted equal to the fixture set, so a sixth server frame lands as a missing fixture rather than a silently dropped frame. The parser does not CALL the schema (it is stricter than a client should be about id SHAPE — all four frame fixtures the plan's own test file carries are refused by it: purge, caught-up and error on id shape alone, and the event frame on id shape plus `clientTime`/`serverTime` ISO format plus the `workspaceSeq` the plan's envelope never carried; the schema's docblock says nothing in the repo parses with it; and a value import would resolve through `./dist`), except on `envelope.workspaceSeq`, where it is exactly as strict: a positive integer, required, so a frame the subscriber could not resume from is refused rather than turned into `NaN`. (Planted defects, counts from the final battery against the shipped file: dropping the `scope-revoked` branch kills 4 cases; dropping the `workspaceSeq` guard kills 1; guessing at an unknown `type` kills 1.) — `packages/app-core/test/online/stream.test.ts`
- **3.34** ✅ Online stream subscriber — the resume and lifecycle half. The subscribe frame carries the CURRENT cursor on every (re)connect; reconnects use the capped jittered backoff and the attempt counter resets on a successful open; unsubscribe closes the socket and stops reconnecting. The cursor advances from `caught-up`'s `seq` AND from an event's `envelope.workspaceSeq` — never from the per-entity `envelope.seq`, pinned with a fixture whose two counters are deliberately different numbers (`seq: 12`, `workspaceSeq: 4`) so all three outcomes are distinguishable — guarded by `Math.max` so an at-least-once replay below the cursor cannot drag it back, and applied only AFTER the consumer callback returns, so a throwing consumer leaves the cursor where it was — asserted for BOTH advancing frames, since a comment covering two advances with only one tested is the shape of claim this repo keeps finding. `purge` moves no cursor and is delivered every time it arrives (de-duplication is the consumer's). Frames addressed to another workspace are dropped and move nothing, `scope-revoked` included — a foreign revocation must not end this subscription. `scope-revoked` for THIS workspace is terminal: delivered once, then the subscriber closes and never reconnects, and the caller's `Unsubscribe` handle stays safe to call. A shell whose `close()` dispatches `onclose` synchronously (legal for the injected `WebSocketLike`, unlike the DOM socket) is stopped clean — asserted on `vi.getTimerCount()`, because `connect()`'s own `closed` guard means a socket count alone cannot see the retry timer that would otherwise be left scheduled.
