# Home (Knowledge Graph spec E) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In the gisik orchestration, every task is ONE lane session. Follow `gisik-nokma-lanes/STEPS-common-2026-10-03.md`: numbered steps, each ending with a pushed commit + `CHECKPOINT task/<branch> <sha40> step <n>/<N>` + `HANDOFF-<branch>.md`; the sweep list + your own mutation pass before DONE.

**Goal:** a Home page at `/`, reached from the nav brand (now a link), showing six numbers for the current workspace — Tickets, Open, Past due, Due in N days, Members, Notes — over the workspace's Knowledge Graph, where pressing a number lights its items on the graph.

**Architecture:**
- **Server.** One read, `GET /v1/workspaces/:workspaceId/home`. It is ONE light ticket SELECT, a notes SELECT and the roster query. Counts and capped ids come from the same rows. The due rule is `classifyDue` (`routes/attention.ts:321`), and visibility is `visibleTicketsWhere` / `visibleNotesWhere` / `ROSTER_VISIBLE_CLAUSE`: consumed, never restated.
- **Client.** `DataSource.query.getHome` → `apps/web/src/home/*`. `app/page.tsx` stops redirecting and renders `HomeScreen`. `NavBrand` becomes a `next/link` to `/`, with a non-link variant kept for the skeleton.
- **Graph.** The graph is plan C's `KnowledgeGraph` React component in its Home configuration. E passes a centre, a hop count and a highlight set, and reads back which ids are clear. The contract is pinned in Task 4 and in "The plan C contract" below.

**Tech stack:** Fastify + Postgres (server), React 19 / Next 15 App Router (web), `@gisik-nokma/app-core` DataSource, vitest 3 (jsdom), Playwright (plan C's `packages/knowledge-graph-browser` harness), Sigma v4 via plan C's seam.

**Spec:** `docs/superpowers/specs/2026-10-03-home-design.md`. Read it first; its section numbers (§) are cited below. Spec C (`2026-10-03-knowledge-graph-view-design.md`) §3, §6.4 and §9 define the component Task 4 consumes.

**Decisions this plan takes where the spec is silent** (each is reported to the planner and is one branch to change)
- **D-E1 Open.** "Open" means `state_category <> 'terminal' AND closed_at IS NULL`. The enum is `open|active|terminal` (`packages/domain/src/workflow.ts:4`), so the spec's "done category" is `terminal`. A CLOSED ticket is not open, whatever its state; `readAttention` makes the same exclusion (`routes/attention.ts:188`). Past due and Due soon are subsets of Open.
- **D-E2 Archived projects are counted.** The spec excludes only the trash, so `LIVE_TICKET_WHERE` applies plus notes' `deleted = FALSE` / `NOTE_PROJECT_LIVE_WHERE`. That makes Past due / Due soon EQUAL attention's overdue / due-soon buckets: `readAttention` does not drop archived projects either. Case 27.611 pins the agreement. (The workspace-scope list does drop them, `routes/list.ts:126-133`; if the owner prefers that rule, T1 adds one conjunct and 27.611 changes.)
- **D-E3 Guests.**
  - **Their visible counts.** A guest is served counts and ids over their own visible tickets and notes. The ids are items the graph shows them anyway, and the count is the length of a list they receive.
  - **No Members count.** A guest is served `members: null` and `ids.members: []`, and the tile reads "Restricted": the roster refuses a guest (`read/workspace-counts.ts:128-146`), and `visibleMemberCount` returns null for one.
  - **Not the directory card's rule.** The directory card withholds per-project ticket volume from guests (`workspace-counts.ts:42-53`, `:74`). Home does not follow it, for the reason given in the first sub-point.
- **D-E4 The workspace shown** waits for a signed-in session (never the first workspace for a frame), then is the remembered one (`useLastWorkspace`, `apps/web/src/use-last-workspace.ts`) when it is in the viewer's live workspaces. Otherwise it is the first live workspace from `getMyWorkspaces()`, and with no live workspace the empty state shows. An archived remembered workspace falls through to the first live one.
- **D-E5 The brand everywhere.** `NavBrand` links to `/` in `AppNav` AND `LegalNav`: one component, one brand. The skeleton (`AppNavSkeleton`) keeps a non-link brand (case 25.057 asserts the skeleton holds no `a`).
- **D-E6 No `aria-current` on the brand.** `.gn-nav a[aria-current='page']` would draw the raised tab look and the indicator bar on the brand (`globals.css:3038`).
- **D-E7 The accessible name "Gisik Nokma, Home"** comes from `aria-labelledby` on a `gn-visually-hidden` span:
  - **not `aria-label`:** case 13.1476 forbids it on the brand subtree;
  - **not the wordmark:** the wordmark is `display:none` below 40rem (case 13.1494), so it cannot carry the phone name.
- **D-E8 Sign-in still lands on `/workspaces`.** `DEFAULT_NEXT` (`app/sign-in/page.tsx:78`) is unchanged. A signed-out visitor sent from `/` comes back to `/` through `?next=/`.
- **D-E9 MCP.** `get_workspace` always carries `home: { counts, dueSoonDays }`, at one extra GET per call, and no ids: an assistant lists items with `list_tickets` / `list_notes`. Case 14.305's exact `toEqual` is updated in the same commit.

  ```ts
  import type { FastifyInstance, preHandlerHookHandler } from 'fastify';
  import { HOME_ID_CAP, istDayOf, type FieldClaim, type HomeResponse, type StateCategory } from '@gisik-nokma/domain';
  import type { Queryable } from '../db/queryable.js';

  import { NOTE_PROJECT_LIVE_WHERE } from '../read/notes.js';

  import { dueDateOfClaim } from '../read/ticket-cards.js';
  import { LIVE_TICKET_WHERE, visibleNotesWhere, visibleTicketsWhere } from '../read/visible-where.js';
  import { visibleMemberIds } from '../read/workspace-counts.js';
  import { addIstDays, classifyDue } from './attention.js';

  type HomeTicketRow = { ticket_id: string; state_category: StateCategory; closed: boolean; due_claim: FieldClaim | null };
  type Dated = { id: string; day: string };

  /** The first `HOME_ID_CAP` ids, in the order given. The count is taken BEFORE this, never after. */
  export function capIds(ids: readonly string[]): string[] {
    return ids.slice(0, HOME_ID_CAP);
  }

  const byDayThenId = (a: Dated, b: Dated): number =>
    a.day < b.day ? -1 : a.day > b.day ? 1 : a.id < b.id ? -1 : a.id > b.id ? 1 : 0;

  /**
   * Home's six numbers (spec E §2.2, §2.4). ONE ticket SELECT supplies Tickets, Open, Past due and Due soon: the
   * counts are lengths of the id lists built from the same rows, so a count and the items it lights cannot
   * disagree. It selects four columns, never a card — `readAttention` assembles a full card per ticket and would
   * not meet the 120 ms budget (27.600).
   *
   * - Visibility is `visibleTicketsWhere` / `visibleNotesWhere` / the roster clause, CONSUMED (as attention does).
   * - The trash is `LIVE_TICKET_WHERE` and `n.deleted = FALSE` + `NOTE_PROJECT_LIVE_WHERE` (as `listNotes` does).
   * - Open = not `terminal` and not closed (decision D-E1, the same exclusion `readAttention` makes at :188).
   * - Past due / Due soon = `classifyDue` over the claimed due day only (`dueDateOfClaim`), today and the horizon
   *   in IST from `now` and the workspace's `dueSoonDays` (attention's own arithmetic, `addIstDays`).
   * - Archived projects are counted (D-E2), which is what makes 27.611's agreement with attention exact.
   */
  export async function readHome(
    db: Queryable,
    eff: EffectiveRole,
    viewerId: string,
    workspaceId: string,
    now: Date,
  ): Promise<HomeResponse> {
    const settings = await getWorkspaceSettings(db, workspaceId);
    const today = istDayOf(now.toISOString());
    const horizon = addIstDays(today, settings.dueSoonDays);

    const params = new SqlParams();
    const where = [`t.workspace_id = ${params.add(workspaceId)}`, visibleTicketsWhere(eff, viewerId, params), LIVE_TICKET_WHERE];
    const { rows } = await db.query<HomeTicketRow>(
      `SELECT t.ticket_id, t.state_category, (t.closed_at IS NOT NULL) AS closed, t.fields -> 'dueDate' AS due_claim
         FROM proj_tickets t
         JOIN proj_visibility v ON v.ticket_id = t.ticket_id
        WHERE ${where.join(' AND ')}
        ORDER BY t.ticket_id DESC`,
      params.toArray(),
    );

    const tickets: string[] = [];
    const open: string[] = [];
    const pastDue: Dated[] = [];
    const dueSoon: Dated[] = [];
    for (const row of rows) {
      tickets.push(row.ticket_id);
      if (row.state_category === 'terminal' || row.closed) continue;
      open.push(row.ticket_id);
      const due = dueDateOfClaim(row.due_claim ?? undefined, row.ticket_id);
      if (due.state !== 'claimed') continue;
      const verdict = classifyDue(due.claim.date, today, horizon);
      if (verdict === null) continue;
      (verdict.kind === 'overdue' ? pastDue : dueSoon).push({ id: row.ticket_id, day: due.claim.date });
    }
    pastDue.sort(byDayThenId);
    dueSoon.sort(byDayThenId);

    const noteParams = new SqlParams();
    const noteWhere = [
      `n.workspace_id = ${noteParams.add(workspaceId)}`,
      visibleNotesWhere(eff, viewerId, noteParams),
      NOTE_PROJECT_LIVE_WHERE,
      'n.deleted = FALSE',
    ];
    const { rows: noteRows } = await db.query<{ note_id: string }>(
      `SELECT n.note_id FROM proj_notes n WHERE ${noteWhere.join(' AND ')} ORDER BY n.updated_at DESC, n.note_id`,
      noteParams.toArray(),
    );
    const notes = noteRows.map((row) => row.note_id);
    const members = await visibleMemberIds(db, eff, workspaceId);

    return {
      workspaceId,
      generatedAt: now.toISOString(),
      dueSoonDays: settings.dueSoonDays,
      counts: {
        tickets: tickets.length,
        open: open.length,
        pastDue: pastDue.length,
        dueSoon: dueSoon.length,
        members: members === null ? null : members.length,
        notes: notes.length,
      },
      ids: {
        tickets: capIds(tickets),
        open: capIds(open),
        pastDue: capIds(pastDue.map((d) => d.id)),
        dueSoon: capIds(dueSoon.map((d) => d.id)),
        members: capIds(members ?? []),
        notes: capIds(notes),
      },
    };
  }

  /** `GET /v1/workspaces/:workspaceId/home` — attention's door exactly: 401 by the preHandler, 404 by `requireMember`. */
  export function registerHomeRoutes(
    app: FastifyInstance,
    deps: { pool: Queryable; now?: () => Date },
    requireSession: preHandlerHookHandler,
  ): void {
    const now = deps.now ?? ((): Date => new Date());
    app.get<{ Params: { workspaceId: string } }>(
      '/v1/workspaces/:workspaceId/home',
      { preHandler: requireSession },
      async (request, reply) => {
        const { workspaceId } = request.params;
        const viewerId = request.currentUserId;
        const eff = await requireMember(deps.pool, viewerId, workspaceId);
        if (eff === null) return reply.status(404).send(READ_NOT_FOUND_BODY);
        return readHome(deps.pool, eff, viewerId, workspaceId, now());
      },
    );
  }
  ```

  ```ts
  import type { WorkspaceRef } from '@gisik-nokma/app-core';
  import type { LastWorkspace } from '../use-last-workspace.js';

  export type HomeWorkspace = { status: 'loading' } | { status: 'none' } | { status: 'ready'; workspace: WorkspaceRef };

  /**
   * Which workspace Home shows (spec E assumption "the current one (the switcher's)"; decision D-E4): the remembered
   * one when it is among the viewer's LIVE workspaces, else the first live one, else none. Never a remembered id
   * the directory does not contain — Home must not ask the server for a workspace the viewer cannot reach.
   * The caller passes `{ status: 'unknown' }` until the session is SIGNED IN (27.628's ordering case).
   */
  export function resolveHomeWorkspace(remembered: LastWorkspace, workspaces: readonly WorkspaceRef[] | null): HomeWorkspace {
    if (workspaces === null || remembered.status === 'unknown') return { status: 'loading' };
    const live = workspaces.filter((workspace) => !workspace.archived);
    if (remembered.status === 'remembered') {
      const hit = live.find((workspace) => workspace.id === remembered.workspaceId);
      if (hit !== undefined) return { status: 'ready', workspace: hit };
    }
    const first = live[0];
    return first === undefined ? { status: 'none' } : { status: 'ready', workspace: first };
  }
  ```

  ```ts
  import type { HomeNumberKey, HomeResponse } from '@gisik-nokma/domain';

  /**
   * Which number is lit (spec E §2.3). Clicking the lit one clears it; another switches; Escape clears — unless
   * something nearer the focus already handled that Escape (`defaultPrevented`: an open menu, the graph's own
   * `onEscape`, T4). A reload that drops the lit number to 0 clears it (Review Focus 5).
   */
  export function useHomeHighlight(home: HomeResponse | null) {
    const [pressed, setPressed] = useState<HomeNumberKey | null>(null);
    const toggle = useCallback((key: HomeNumberKey) => setPressed((current) => (current === key ? null : key)), []);
    const clear = useCallback(() => setPressed(null), []);
    useEffect(() => {
      if (pressed !== null && home !== null && home.counts[pressed] === 0) setPressed(null);
    }, [home, pressed]);
    useEffect(() => {
      if (pressed === null) return undefined;
      const onKey = (event: KeyboardEvent): void => {
        if (event.key !== 'Escape' || event.defaultPrevented) return;
        event.preventDefault();
        setPressed(null);
      };
      window.addEventListener('keydown', onKey);
      return () => window.removeEventListener('keydown', onKey);
    }, [pressed]);
    return { pressed, toggle, clear };
  }
  ```

  ```tsx
  export function highlightNote(a: { key: HomeNumberKey; total: number; lit: number; further: number; dueSoonDays: number }): { text: string; further: number } {
  ```
