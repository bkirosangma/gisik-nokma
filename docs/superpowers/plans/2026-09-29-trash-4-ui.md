# Trash — Plan 4 of 4: UI (the delete dialog, archive and delete on the cards, Account → Deleted items) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Every task that touches a screen ALSO invokes `ui-ux-pro-max` beside its workflow skill (workspace `CLAUDE.md`, "UI/UX Design"); the design decisions it would make are already pinned below and applied through this repo's own tokens and components, so the skill is a second opinion on spacing, focus and contrast, not a licence to restyle.

**Goal:** Put a face on Plan 1's lifecycle. Every delete asks through one shared dialog: the item is named, there is a **Delete permanently** switch (off by default), and a note is always visible. Submitting sends `*.deleted`, plus `purge.marked` when the switch is on, in ONE ingest batch. The dialog is used by four doors:
- the ticket sheet;
- a note's page — a door that does not exist today;
- a project card on the workspace home;
- a workspace card on `/workspaces`.

Each workspace card gets an owner-only overflow menu (Archive / Restore, Delete…), and archived workspaces move to a collapsed **Archived** group. `/account` gains **Deleted items**, listing what you may restore or mark, with Restore, Mark for permanent deletion and Unmark, and each marked row showing **Permanently deleted on <IST day>**.

**Architecture:**
- **Pure pieces in `packages/app-core/src/trash/`**, each unit-tested with no DOM:
  - `copy.ts`: every user-visible string, as exported constants;
  - `seeds.ts`: which events each act sends, in which order;
  - `batch.ts`: what an ingest answer MEANS, including the half-committed batch;
  - `dates.ts`: the IST day and the overdue test.
- **Two shared views in `packages/app-core`.** `views/delete-dialog.tsx` (`DeleteDialog`) and `account/deleted-items-section.tsx` (`DeletedItemsSection`) own their own submit, double-submit latch and inline refusal, so every host gets the same behaviour.
- **The hosts are thin.** They are the ticket sheet (app-core), the project page's toast/undo, the note page, the workspace home and `/workspaces` (all `apps/web`). Each decides only WHO sees the door and what to reload afterwards.
- **One additive server change.** `DeletedItem.deletedByName` exists so the list can say who deleted an item.
- **Two small `packages/ui` changes.** `Dialog` gains `initialFocusRef` / `role` / `describedBy`, and `Button` forwards `ref`, so Cancel can take the default focus.

**Tech Stack:** TypeScript monorepo (pnpm + turbo); React 19 (`ref` is a plain prop); `@react-aria/focus` (already under `Dialog`); vitest + Testing Library + jsdom in `packages/ui`, `packages/app-core` and `apps/web`; Fastify + `pg` for the one server read (test Postgres on 54329).

**Spec:** `docs/superpowers/specs/2026-09-23-trash-and-purge-design.md` (owner-approved; decisions T1–T11 — T11 landed on `origin/release/trash` with #740). This plan implements §6.1, §6.2, §6.3's screen and §7's UI half (a refusal is shown inline and the dialog stays open). Read the spec's §2, §4 (the refusals and the authority matrix) and §6 before Task 1. Plan 1 (`docs/superpowers/plans/2026-09-23-trash-1-lifecycle-core.md`, landed #737) is where every event and refusal this plan sends and shows comes from.

## Recorded deviations from the spec

- **D1 — `DeletedItem` gains `deletedByName: string | null`.** Spec §6.3 wants each row to say who deleted the item, and Plan 1's read serves only `deletedBy`, a user id (`packages/domain/src/read-models.ts:891`).
  - The client cannot resolve it. A deleted workspace has no roster a member may read, and the replica's `getMembers` is itself a gap.
  - The server joins `"user"` exactly as `pendingFor` does for an inviter (`apps/server/src/routes/my-invitations.ts:138-152`: `LEFT JOIN "user"`; a user who has gone is `null`). A blank name is also `null`.
  - The row says **you** when `deletedBy` is the viewer, the name when there is one, and **someone** otherwise. Task 2.
- **D2 — the note page has no Delete today; this plan adds the door.** Spec §6.1 lists "note page" among the existing delete doors.
  - Measured: `docs/manual.md:1650` says "there is no Delete button on a note's own page", and `docs/faq.md:588` says the same. `apps/web/src/notes/` has no `note.deleted` sender at all (`git grep "'note.deleted'" -- apps/web` finds nothing).
  - Task 6 adds **Delete…** to the note's byline for whoever may edit the note (`note-document.tsx:389-392`'s `canEdit`: author, workspace admin or owner — the `NOTE_AUTHOR_EVENTS` audience).
- **D3 — the project page has no Archive, so Delete… lives on the workspace home only.** Spec §6.2 says "workspace home / project page: Delete… beside the existing Archive". The project page draws only an `Archived` chip (`apps/web/app/w/[workspaceId]/p/[projectId]/page.tsx:2329-2331`); the Archive control is on the home's `ProjectCard` (`apps/web/app/w/[workspaceId]/page.tsx:452-465`). Delete… goes beside it there (Task 7).
- **D4 — who sees each door.** Brief: "show a door only to whoever may use it".
  - **Ticket sheet: unchanged — Delete stays visible to everyone.** Its own ruling (`packages/app-core/src/views/ticket-sheet.tsx:2048-2056`, "A hidden control cannot explain itself") keeps it, and the server still refuses.
  - **The three new doors are hidden from anyone who cannot use them:**
    - the workspace menu from anyone but the owner (`WorkspaceRef.role === 'owner'`; spec §4: workspace acts are owner-only, `WORKSPACE_OWNER_ONLY_REASON`, `check-permission.ts:111`);

    - note Delete… from anyone `canEdit` refuses.
  - Deleted items lists only what the server says the caller may act on (T3), so every row's controls are shown.

    - the confirm keeps the accessible name `Delete ticket` (D8).
  - Case 13.1183's prose is amended, not renumbered.

- **D8 — the confirm's accessible name.**
  - The spec's visible labels are `Delete` / `Delete permanently`. The footer control is already called `Delete`, and 13.1183 pins exactly one button with that name.
  - So the confirm's accessible name is `Delete <kind>` with the switch off (it CONTAINS the visible `Delete`, so WCAG 2.5.3 Label in Name holds), and `Delete permanently` with it on (equal to the visible text; the switch of the same name is a `checkbox`, a different role).
  - Existing tests that press `Delete ticket` keep working unchanged.
- **D9 — Cancel takes the default focus through a new `Dialog` prop.**
  - `Dialog` focuses its PANEL on open (`packages/ui/src/components/dialog.tsx:95-98`, ruling P8: announce the dialog's name). A child's `autoFocus` runs first and is then overwritten.
  - `initialFocusRef` is optional and the default is unchanged. Focus lands INSIDE the `alertdialog`, whose name is still announced on entry.
- **D10 — a half-committed batch is handled; the spec is silent on it.**
  - The ingest door commits each event of a batch independently (`apps/server/src/ingest/ingest-service.ts:413-427`: one `commitOne` per event), so `[x.deleted, purge.marked]` can commit the delete and refuse the mark.
  - Retrying would resend `x.deleted` and meet `ALREADY_DELETED_REASON`. So the dialog says so and offers only **Close**:
    - it says "This <kind> was deleted, but not marked for permanent deletion — <reason> You can mark it from Deleted items on your Account page.";
    - it tells its host `{ permanent: false }`.
  - The same split on the Undo pair `[purge.unmarked, ticket.restored]` leaves the ticket deleted AND unmarked. The page's next Undo then sends only `ticket.restored`.
- **D11 — the 2026-09-20 post-delete Undo, changed as the spec directs.** After a PERMANENT delete, the toast's Undo and the page strip's Undo send `purge.unmarked` then `ticket.restored` in ONE batch (spec §6.1, "recorded as a deliberate change to that ruling"). After a soft delete they send `ticket.restored` alone, exactly as before.
- **D12 — T8's "hides from lists of live work" is applied to `/workspaces` only.**
  - The other workspace lists (the nav's last-project control, the notes page's sections, Account's "Your workspaces") still list an archived workspace, unmarked.
  - This is a recorded gap for the owner, not built here. Archive removes nobody's access (T8), so nothing is hidden that the person cannot reach.
- **D13 — Deleted items offline.** The replica rejects `getDeletedItems` with `ReplicaGapError` until Plan 3 (`replica-data-source.ts:346-353`, `:1184`; `data-source.ts:248-249`). The section shows **Deleted items needs a connection.** and never `Nothing deleted.`, since an empty list would claim nothing was deleted when nobody was asked.
- **D14 — a marked row offers Unmark, and its Restore is disabled with a visible reason.** The server refuses a restore while marked (`UNMARK_FIRST_REASON`). The spec lists Restore and Mark/Unmark per row without saying how the two interact.
  - A marked row keeps **Restore** visible but disabled, with the text "Unmark it to restore it." beside it (text, never a `title=` tooltip).
  - An overdue row (due, purge not yet run) has no Unmark (spec §4: unmark is refused once due), a disabled Restore, and "Its permanent deletion is under way."

## Review Focus

Inputs and conditions the spec implies that no happy path exercises, most likely first. Each has its test in the owning task.

1. **A half-committed batch.**
   - Condition: the delete commits and the permanent mark is refused.
   - Expected: the dialog says exactly that, never resends the delete, and its only way out reports `{ permanent: false }`.
   - Owners:
     - Task 4, case 19.224;
     - the Undo-pair twin, where the unmark commits and the restore is refused so the next Undo sends only the restore: Task 5, case 19.234.
2. **A refusal mid-dialog.**
   - Condition: the server refuses (for example, an admin deleting a workspace).
   - Expected: the reason shows inline and the dialog stays open, still holding the typed workspace name and the switch position, so a retry is one press.
   - Owner: Task 4, case 19.222.
3. **A double press.**
   - Expected: two presses of the confirm, or of a row action in Deleted items, send ONE batch.
   - Owners: Task 4, case 19.223; Task 9, case 19.256.
4. **Cancel is the default focus, and Escape cancels without collateral.**
   - Condition: the dialog opens, then the person presses Escape.
   - Expected: focus is on Cancel when it opens. Escape posts nothing, and on the ticket sheet it does not also close the sheet underneath.
   - Owners: Task 4, case 19.221; Task 5, case 19.232.
5. **A marked row, and an overdue one.**
   - Expected: a marked row offers Unmark and a disabled Restore with its reason. A row whose due instant has passed still shows its date, with no Unmark.
   - Owners: Task 9, cases 19.254 and 19.255, with `now` injected at, and one millisecond before, the due instant.

import type { EnvelopeSeed } from '../submit.js';

/**
 * Which events each trash act sends, and in which ORDER (trash series Plan 4).
 * Order matters because the ingest door commits a batch one event at a time,
 * in order (`apps/server/src/ingest/ingest-service.ts`'s `ingestAll`):
 *
 * - a permanent delete is `<kind>.deleted` THEN `purge.marked` — the mark is
 *   refused on a live item (`DELETE_FIRST_REASON`), so it must follow the delete;
 * - a restore of a marked item is `purge.unmarked` THEN the restore — the
 *   restore is refused while marked (`UNMARK_FIRST_REASON`).
 *
 * Every payload is `{}`: Plan 1's lifecycle payloads are empty and `.strict()`,
 * and the due date is derived by the server, never claimed.
 */
export type LifecycleTarget = { kind: LifecycleKind; workspaceId: string; entityId: string };

const DELETE_TYPE: Readonly<Record<LifecycleKind, string>> = {
  workspace: 'workspace.deleted',
  project: 'project.deleted',
  ticket: 'ticket.deleted',
  note: 'note.deleted',
};

/**
 * The UNDELETE of each kind. `project.restored`/`workspace.restored` are
 * UN-ARCHIVE (spec §4, "one type = one meaning") and must never appear here —
 * case 19.212's mutation is exactly that swap.
 */
const RESTORE_TYPE: Readonly<Record<LifecycleKind, string>> = {
  workspace: 'workspace.undeleted',
  project: 'project.undeleted',
  ticket: 'ticket.restored',
  note: 'note.restored',
};

function seed(target: LifecycleTarget, type: string): EnvelopeSeed {
  return {
    workspaceId: target.workspaceId,
    entity: { kind: target.kind, id: target.entityId },
    type,
    payload: {},
  };
}

export function deleteSeeds(target: LifecycleTarget, permanent: boolean): EnvelopeSeed[] {
  const deleted = seed(target, DELETE_TYPE[target.kind]);
  return permanent ? [deleted, seed(target, 'purge.marked')] : [deleted];
}

export function restoreSeeds(target: LifecycleTarget, unmarkFirst: boolean): EnvelopeSeed[] {
  const restore = seed(target, RESTORE_TYPE[target.kind]);
  return unmarkFirst ? [seed(target, 'purge.unmarked'), restore] : [restore];
}

export function markSeeds(target: LifecycleTarget): EnvelopeSeed[] {
  return [seed(target, 'purge.marked')];
}

export function unmarkSeeds(target: LifecycleTarget): EnvelopeSeed[] {
  return [seed(target, 'purge.unmarked')];
}

/** T8 — the workspace archive pair, filed against the workspace in its own stream. */
export function archiveWorkspaceSeeds(workspaceId: string, currentlyArchived: boolean): EnvelopeSeed[] {
  return [
    seed(
      { kind: 'workspace', workspaceId, entityId: workspaceId },
      currentlyArchived ? 'workspace.restored' : 'workspace.archived',
    ),
  ];
}

/** A Deleted items row as the thing its buttons act on. A workspace row's `workspaceId` IS its id (`read/deleted-items.ts`). */
export function targetOf(item: DeletedItem): LifecycleTarget {
  return { kind: item.kind, workspaceId: item.workspaceId, entityId: item.id };
}

import type { IngestResult } from '@gisik-nokma/domain';

/**
 * What one ingest answer MEANS for a batch of several claims (trash Plan 4,
 * D10). The door commits each event on its own, in order
 * (`apps/server/src/ingest/ingest-service.ts`'s `ingestAll` — one `commitOne`
 * per event), so a two-event batch has four outcomes, not two:
 *
 * - `committed` — every event committed;
 * - `refused` — none did; `reason` is the first non-committed answer's own
 *   sentence (a refusal's `reason`, or an invalid claim's `message`);
 * - `partly` — some did and some did not; `committed[i]` says which, so a
 *   caller can say WHICH half landed and never resend the half that did;
 * - `unanswered` — fewer answers than claims, so what happened is not known
 *   (the workspace home's own rule, `app/w/[workspaceId]/page.tsx:258-260`).
 */
export type BatchOutcome =
  | { status: 'committed' }
  | { status: 'refused'; reason: string }
  | { status: 'partly'; reason: string; committed: boolean[] }
  | { status: 'unanswered'; answered: number };

export function classifyBatch(results: readonly IngestResult[], sent: number): BatchOutcome {
  if (results.length !== sent) return { status: 'unanswered', answered: results.length };
  const committed = results.map((result) => result.status === 'committed');
  const firstBad = results.find((result) => result.status !== 'committed');
  if (firstBad === undefined) return { status: 'committed' };
  const reason =
    firstBad.status === 'refused' ? firstBad.reason : firstBad.status === 'invalid' ? firstBad.message : '';
  return committed.some(Boolean) ? { status: 'partly', reason, committed } : { status: 'refused', reason };
}

import { useEffect, useId, useRef, useState, type ReactElement } from 'react';
import type { LifecycleKind } from '@gisik-nokma/domain';
import { Button, Dialog, Switch } from '@gisik-nokma/ui';
import type { DataSource } from '../data-source.js';
import type { MakeSubmitted } from '../submit.js';
import { writeFailureCopy, writeFailureRefusalClass } from '../session-expired.js';
import { classifyBatch } from '../trash/batch.js';
import {
  DELETE_CANCEL_LABEL,
  DELETE_CLOSE_LABEL,
  DELETE_NOTE,
  DELETE_PERMANENTLY_LABEL,
  batchMixedLine,
  deleteConfirmAccessibleName,
  deleteConfirmVisibleLabel,
  deleteDialogTitle,
  deleteUnreachableLine,
  deletedNotMarkedLine,
  typeNameLabel,
  unansweredLine,
} from '../trash/copy.js';
import { deleteSeeds } from '../trash/seeds.js';

export type DeleteDialogProps = {
  open: boolean;
  kind: LifecycleKind;
  /** The item's human name — a title, a project or workspace name. */
  name: string;
  workspaceId: string;
  entityId: string;
  dataSource: Pick<DataSource, 'ingest'>;
  make: MakeSubmitted;
  /** Cancel, the ×, the scrim or Escape — nothing committed. */
  onCancel: () => void;
  /** The delete COMMITTED. `permanent` is true only when the mark committed too. */
  onDeleted: (outcome: { permanent: boolean }) => void;
};

/**
 * THE delete confirmation (trash series Plan 4; spec §6.1, §7). Every delete
 * door in the product opens this one component — the ticket sheet, a note's
 * page, a project card, a workspace card — so the switch, the note, the
 * one-batch order and the refusal behaviour cannot drift between them.
 *
 * It owns its submit rather than handing a callback to its host, because §7's
 * rule — "the dialog shows it inline and keeps the dialog open" — is about
 * THIS surface, and a host-owned submit would need every host to thread a
 * refusal back in.
 *
 * `open` false renders nothing, and each opening mounts a FRESH body: the
 * switch and the typed name start empty every time, but a refusal inside one
 * opening keeps both (Review Focus 2, case 19.222).
 */
export function DeleteDialog(props: DeleteDialogProps): ReactElement | null {
  if (!props.open) return null;
  return <DeleteDialogBody {...props} />;
}

type Phase =
  | { at: 'asking'; notice: { text: string; className: string } | null }
  | { at: 'partly'; text: string };

function DeleteDialogBody({
  kind,
  name,
  workspaceId,
  entityId,
  dataSource,
  make,
  onCancel,
  onDeleted,
}: DeleteDialogProps): ReactElement {
  const [permanent, setPermanent] = useState(false);
  const [typed, setTyped] = useState('');
  const [phase, setPhase] = useState<Phase>({ at: 'asking', notice: null });
  const [submitting, setSubmitting] = useState(false);
  // Set SYNCHRONOUSLY before the first await, so a second press in the same
  // tick is refused even before React re-renders `disabled` (the ticket
  // sheet's title latch records why render state alone cannot do this).
  const inFlight = useRef(false);
  const cancelRef = useRef<HTMLButtonElement | null>(null);
  const closeRef = useRef<HTMLButtonElement | null>(null);
  const noteId = useId();
  const nameId = useId();
  const needsTypedName = kind === 'workspace';
  const nameMatches = !needsTypedName || typed.trim() === name.trim();

  // D10's Close takes the focus the confirm had: the confirm is gone, and a
  // person who pressed it must land on the one thing left to press.
  useEffect(() => {
    if (phase.at === 'partly') closeRef.current?.focus();
  }, [phase.at]);

  const finishPartly = (): void => onDeleted({ permanent: false });

  const submit = async (): Promise<void> => {
    if (inFlight.current || !nameMatches) return;
    inFlight.current = true;
    setSubmitting(true);
    const seeds = deleteSeeds({ kind, workspaceId, entityId }, permanent);
    try {
      const results = await dataSource.ingest(seeds.map(make));
      const outcome = classifyBatch(results, seeds.length);
      if (outcome.status === 'committed') {
        onDeleted({ permanent });
        return;
      }
      if (outcome.status === 'partly') {
        setPhase({
          at: 'partly',
          text: outcome.committed[0] === true ? deletedNotMarkedLine(kind, outcome.reason) : batchMixedLine(outcome.reason),
        });
        return;
      }
      if (outcome.status === 'refused') {
        setPhase({ at: 'asking', notice: { text: outcome.reason, className: 'gn-refusal gn-refusal--server' } });
        return;
      }
      setPhase({
        at: 'asking',
        notice: { text: unansweredLine(outcome.answered, seeds.length), className: 'gn-refusal gn-refusal--transport' },
      });
    } catch (cause) {
      const text = writeFailureCopy(cause, deleteUnreachableLine);
      setPhase({ at: 'asking', notice: { text, className: writeFailureRefusalClass(text) } });
    } finally {
      inFlight.current = false;
      setSubmitting(false);
    }
  };

  const title = deleteDialogTitle(kind, name);

  if (phase.at === 'partly') {
    return (
      <Dialog open title={title} onClose={finishPartly} role="alertdialog" initialFocusRef={closeRef}>
        <div className="gn-delete-dialog">
          <p role="alert" className="gn-refusal gn-refusal--server">
            {phase.text}
          </p>
          <div className="gn-delete-dialog__actions">
            <Button ref={closeRef} onClick={finishPartly}>
              {DELETE_CLOSE_LABEL}
            </Button>
          </div>
        </div>
      </Dialog>
    );
  }

  return (
    <Dialog
      open
      title={title}
      onClose={onCancel}
      role="alertdialog"
      initialFocusRef={cancelRef}
      describedBy={noteId}
    >
      <div className="gn-delete-dialog">
        {needsTypedName ? (
          <div className="gn-field gn-delete-dialog__name">
            <label className="gn-field__label" htmlFor={nameId}>
              {typeNameLabel(name)}
            </label>
            <input
              id={nameId}
              className="gn-field__input"
              value={typed}
              autoComplete="off"
              spellCheck={false}
              onChange={(event) => setTyped(event.target.value)}
            />
          </div>
        ) : null}
        <Switch checked={permanent} onChange={setPermanent} className="gn-delete-dialog__switch">
          {DELETE_PERMANENTLY_LABEL}
        </Switch>
        <p id={noteId} className="gn-delete-dialog__note">
          {DELETE_NOTE}
        </p>
        {phase.notice !== null ? (
          <p role="alert" className={phase.notice.className}>
            {phase.notice.text}
          </p>
        ) : null}
        <div className="gn-delete-dialog__actions">
          <Button ref={cancelRef} onClick={onCancel}>
            {DELETE_CANCEL_LABEL}
          </Button>
          <Button
            variant="danger"
            aria-label={deleteConfirmAccessibleName(kind, permanent)}
            disabled={submitting || !nameMatches}
            onClick={() => void submit()}
          >
            {deleteConfirmVisibleLabel(permanent)}
          </Button>

/**
 * The workspace card's overflow menu (trash Plan 4, spec §6.2): **Archive** /
 * **Restore** and **Delete…**, for the workspace OWNER only — the caller does
 * not render it for anyone else (D4; spec §4: workspace acts are owner-only).
 *
 * ## AccountMenu's recipe, not a new one
 *
 * `account-menu.tsx` is the product's menu: a trigger with `aria-haspopup` and
 * `aria-expanded`, a NAMED `role="menu"` (case 13.1059's sweep reads the
 * opening tag), the first item focused on open, ArrowUp/ArrowDown cycling,
 * Escape closing and returning focus to the trigger, and a pointer-down outside
 * closing it. This is that recipe for a card.
 *
 * ## It is a SIBLING of the card's door, never inside it (D5)
 *
 * The card body is one `<Link>` (Round 19c); a button nested in a link is
 * invalid interactive content and would be announced as part of the door. The
 * caller renders this beside the link, inside the same `Card`.
 *
 * ## The menu closes, returning focus to the trigger, BEFORE either act
 *
 * Delete… opens `DeleteDialog`, whose `FocusScope restoreFocus` returns focus
 * to whatever held it when the dialog mounted. That must be this trigger — an
 * unmounted menu item would leave focus on `<body>`.
 */
export function WorkspaceCardMenu({
  name,
  archived,
  disabled,
  onArchiveToggle,
  onDelete,
}: {
  name: string;
  archived: boolean;
  disabled: boolean;
  onArchiveToggle: () => void;
  onDelete: () => void;
}): ReactElement {
  const [open, setOpen] = useState(false);
  const triggerRef = useRef<HTMLButtonElement | null>(null);
  const menuRef = useRef<HTMLDivElement | null>(null);
  const menuId = useId();

  const close = useCallback((returnFocus: boolean) => {
    setOpen(false);
    if (returnFocus) triggerRef.current?.focus();
  }, []);

  useEffect(() => {
    if (!open) return;
    menuRef.current?.querySelector<HTMLElement>('[role="menuitem"]')?.focus();
  }, [open]);

  useEffect(() => {
    if (!open) return;
    const onKeyDown = (event: KeyboardEvent): void => {
      if (event.key === 'Escape') {
        event.stopPropagation();
        close(true);
        return;
      }
      if (event.key !== 'ArrowDown' && event.key !== 'ArrowUp') return;
      const items = [...(menuRef.current?.querySelectorAll<HTMLElement>('[role="menuitem"]') ?? [])];
      if (items.length === 0) return;
      const at = items.indexOf(document.activeElement as HTMLElement);
      const step = event.key === 'ArrowDown' ? 1 : -1;
      const next = at === -1 ? 0 : (at + step + items.length) % items.length;
      event.preventDefault();
      items[next]?.focus();
    };
    const onPointerDown = (event: PointerEvent): void => {
      const target = event.target as Node | null;
      if (target === null) return;
      if (menuRef.current?.contains(target) === true) return;
      if (triggerRef.current?.contains(target) === true) return;
      close(false);
    };
    document.addEventListener('keydown', onKeyDown);
    document.addEventListener('pointerdown', onPointerDown);
    return () => {
      document.removeEventListener('keydown', onKeyDown);
      document.removeEventListener('pointerdown', onPointerDown);
    };
  }, [open, close]);

  return (
    <div className="gn-card-menu">
      <button
        ref={triggerRef}
        type="button"
        className="gn-card-menu__trigger"
        aria-haspopup="menu"
        aria-expanded={open}
        aria-controls={open ? menuId : undefined}
        aria-label={moreActionsFor(name)}
        disabled={disabled}
        onClick={() => setOpen((wasOpen) => !wasOpen)}
      >
        {/* Decorative: the accessible name above says what this is. */}
        <svg width="20" height="20" viewBox="0 0 24 24" fill="currentColor" aria-hidden="true">
          <circle cx="5" cy="12" r="1.75" />
          <circle cx="12" cy="12" r="1.75" />
          <circle cx="19" cy="12" r="1.75" />
        </svg>
      </button>
      {open ? (
        <div ref={menuRef} id={menuId} role="menu" aria-label={WORKSPACE_MENU_LABEL} className="gn-card-menu__list">
          <button
            type="button"
            role="menuitem"
            className="gn-card-menu__item"
            onClick={() => {
              close(true);
              onArchiveToggle();
            }}
          >
            {archived ? RESTORE_LABEL : ARCHIVE_LABEL}
          </button>
          <button
            type="button"
            role="menuitem"
            className="gn-card-menu__item"
            onClick={() => {
              close(true);
              onDelete();
            }}
          >
            {DELETE_TRIGGER_LABEL}
          </button>
        </div>
      ) : null}
    </div>
  );
}

  dataSource: Pick<DataSource, 'ingest' | 'query'>;
  currentUserId: string;
  /** Injected so "overdue" is testable at the due instant; the page omits it. */

  | { at: 'loading' }
  | { at: 'ready'; items: DeletedItem[] }
  | { at: 'offline' }
  | { at: 'failed'; message: string };

type RowNotice = { id: string; text: string; className: string };

/**
 * Account → Deleted items (trash series Plan 4; spec §6.3, §7). Every deleted
 * workspace, project, ticket or note this person may act on (T3 — the server
 * decides; this lists what `GET /v1/me/deleted-items` serves, in its order,
 * newest first).
 *
 * ## Three states that are NOT the empty list (D13)
 *
 * "Nothing deleted." is a claim about the account. The replica cannot answer
 * this read until Plan 3 (`ReplicaGapError`) and a server can fail; neither may
 * be painted as that claim — the reasoning Plan 1 gave for the replica's
 * rejection (`replica-data-source.ts`'s `DELETED_ITEMS_ABSENCES`). The offline
 * case is recognised by the error's NAME (`ReplicaGapError`, set in its
 * constructor), so this view does not import the replica module.
 *
 * ## A marked row cannot be restored — the server says so, and so does the row (D14)
 *
 * `*.undeleted`/`*.restored` are refused while marked (`UNMARK_FIRST_REASON`),
 * and an unmark is refused once due (`PURGE_DUE_REASON`). The row states both
 * as visible text beside a disabled Restore rather than offering a press the
 * server will refuse.
 */
export function DeletedItemsSection({
  dataSource,
  currentUserId,
  now = () => new Date(),
}: DeletedItemsSectionProps): ReactElement {
  const headingId = useId();
  const [load, setLoad] = useState<Load>({ at: 'loading' });
  const [busyId, setBusyId] = useState<string | null>(null);
  const [notice, setNotice] = useState<RowNotice | null>(null);
  // Set synchronously before the first await: a second press in the same tick
  // is refused before React re-renders `disabled`.
  const busyRef = useRef<string | null>(null);

  const reload = useCallback(() => {
    dataSource.query.getDeletedItems().then(
      (items) => setLoad({ at: 'ready', items }),
      (cause: unknown) => {
        if (cause instanceof Error && cause.name === 'ReplicaGapError') setLoad({ at: 'offline' });
        else setLoad({ at: 'failed', message: cause instanceof Error ? cause.message : String(cause) });
      },
    );
  }, [dataSource]);

  useEffect(() => reload(), [reload]);

  const act = async (item: DeletedItem, seeds: EnvelopeSeed[]): Promise<void> => {
    if (busyRef.current !== null) return;
    busyRef.current = item.id;
    setBusyId(item.id);
    setNotice(null);
    const make = makeSubmittedFactory({ actorId: currentUserId, origin: 'web' });
    try {
      const results = await dataSource.ingest(seeds.map(make));
      const outcome = classifyBatch(results, seeds.length);
      if (outcome.status === 'unanswered') {
        setNotice({ id: item.id, text: unansweredLine(outcome.answered, seeds.length), className: 'gn-refusal gn-refusal--transport' });
      } else if (outcome.status !== 'committed') {
        setNotice({ id: item.id, text: outcome.reason, className: 'gn-refusal gn-refusal--server' });
      }
      // Re-read on every answer: a committed act moved the row, and a refused
      // or half-committed one may have changed the world under it.
      reload();
    } catch (cause) {
      const text = writeFailureCopy(cause, changeUnreachableLine);
      setNotice({ id: item.id, text, className: writeFailureRefusalClass(text) });
    } finally {
      busyRef.current = null;
      setBusyId(null);
    }
  };

  const at = now();

  return (
    <section className="gn-account__section gn-deleted-items" aria-labelledby={headingId}>
      <h2 className="gn-account__section-title" id={headingId}>
        {DELETED_ITEMS_HEADING}
      </h2>
      {load.at === 'loading' ? <p className="gn-account__note">{DELETED_ITEMS_LOADING}</p> : null}
      {load.at === 'offline' ? <p className="gn-account__note">{DELETED_ITEMS_OFFLINE}</p> : null}
      {load.at === 'failed' ? (
        <p role="alert" className="gn-refusal gn-refusal--transport">
          {deletedItemsFailed(load.message)}
        </p>
      ) : null}
      {load.at === 'ready' && load.items.length === 0 ? (
        <p className="gn-account__note">{DELETED_ITEMS_EMPTY}</p>
      ) : null}
      {load.at === 'ready' && load.items.length > 0 ? (
        <ul className="gn-deleted-items__list">
          {load.items.map((item) => {
            const label = item.label !== '' ? item.label : KIND_LABEL[item.kind];
            const marked = item.purgeDueAt !== null;
            const overdue = isPurgeOverdue(item.purgeDueAt, at);
            const where = whereLine(item);
            const who =
              item.deletedBy === currentUserId ? DELETED_BY_YOU : (item.deletedByName ?? DELETED_BY_UNKNOWN);
            const inside = containedLine(item.containedCount);
            const busy = busyId !== null;
            const target = targetOf(item);
            return (
              <li key={`${item.kind}:${item.id}`} className="gn-deleted-items__row" data-testid={`deleted-item-${item.id}`}>
                <KindIcon kind={item.kind} />
                <span className="gn-deleted-items__text">
                  <span className="gn-deleted-items__label">{label}</span>
                  <span className="gn-deleted-items__meta">
                    {where === null ? KIND_LABEL[item.kind] : `${KIND_LABEL[item.kind]} · ${where}`}
                  </span>
                  <span className="gn-deleted-items__meta">{deletedByLine(who, istDayLabel(item.deletedAt))}</span>
                  {inside !== null ? <span className="gn-deleted-items__meta">{inside}</span> : null}
                  {item.purgeDueAt !== null ? (
                    <span className="gn-deleted-items__due">{permanentlyDeletedOn(istDayLabel(item.purgeDueAt))}</span>
                  ) : null}
                  {marked ? (
                    <span className="gn-deleted-items__reason">{overdue ? PURGE_UNDER_WAY : UNMARK_BEFORE_RESTORE}</span>
                  ) : null}
                </span>
                <span className="gn-deleted-items__actions">
                  <Button
                    aria-label={restoreItemName(label)}
                    disabled={busy || marked}
                    onClick={() => void act(item, restoreSeeds(target, false))}
                  >
                    {RESTORE_LABEL}
                  </Button>
                  {!marked ? (
                    <Button
                      variant="danger"
                      aria-label={markItemName(label)}
                      disabled={busy}
                      onClick={() => void act(item, markSeeds(target))}
                    >
                      {MARK_LABEL}
                    </Button>
                  ) : null}
                  {marked && !overdue ? (
                    <Button
                      aria-label={unmarkItemName(label)}
                      disabled={busy}
                      onClick={() => void act(item, unmarkSeeds(target))}
                    >
                      {UNMARK_LABEL}
                    </Button>
                  ) : null}
                </span>
                {notice !== null && notice.id === item.id ? (
                  <p role="alert" className={notice.className}>
                    {notice.text}
                  </p>
                ) : null}
              </li>
            );
          })}
        </ul>
      ) : null}
    </section>
  );
}

/** Spec §6.3's "where it lived (workspace › project)". A workspace lived nowhere but itself. */
function whereLine(item: DeletedItem): string | null {
  if (item.kind === 'workspace') return null;
  if (item.kind === 'project' || item.projectName === null) return item.workspaceName;
  return `${item.workspaceName} › ${item.projectName}`;
}
