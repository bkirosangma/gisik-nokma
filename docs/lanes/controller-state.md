### 3. INSTRUMENTS THIS CYCLE
1. **A completion-signal Monitor can match its own dispatch text.** A nudge that quotes the exact expected success string will match its own grep while sitting unsubmitted in the lane's input box. Fix applied both times this cycle: require the trailing id/sha group to be real hex, never the literal example text.
2. **`/exit` inside a multi-line paste is not a command invocation** — it's literal text the agent will (correctly) respond to as content. Send it alone, as its own paste, when the box is otherwise empty.
3. **`check:ctl`'s failure mode hides the checks after it** (`checks.sh`'s loop calls `ctl_fail` and exits immediately on the first red check) — a log showing "N checks ok" and nothing after is a check that never ran the rest, not the whole story.
4. **`ctl_primary()`'s assumptions (`main`, clean, has `.env`) can be legitimately false while the owner uses the primary for their own work — twice this cycle**, once while the primary was on the owner's branch (fixed with a disposable `main` worktree + symlinked `.env`), once after the owner returned it to `main` but a stray uncommitted file (not ours) still failed the cleanliness check (fixed with an exact `git stash push -- <path>` / `pop` around just the checks call — never touch a file whose ownership is unclear any other way). **A worktree holding `main` checked out blocks `git checkout main` anywhere else, including the real primary** — tear down a `GISIK_PRIMARY` scratch worktree the moment its `ctl land` call returns.
5. **A real id-space collision is found by re-measuring against the actual declaration grammar, not by trusting a plan's own provenance note.** `scripts/check-case-ids.mjs`'s line-head regex, applied directly, found one collision a naive `grep -oE '\d+\.\d+' | sort -n` would have MISSED entirely (`7.99` sorts above `7.266` as a float; case ids are (section, integer-sequence) pairs, not decimals — the same trap this repo's own `16.100` vs `16.99` note warns about, reproduced firsthand before catching it).
